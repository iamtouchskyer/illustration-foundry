# Illustration Foundry

A one-stop illustration library for empty / error / loading / success states:
every asset is **generated by script, style-locked, and shipped ready to use**.
One catalog, eight palettes, multiple product lines — any project consumes the
output directly; any change goes through a script, never by hand.

This is an extensible library. Today it ships three product lines drawn from
one 93-subject catalog; new product lines (and new subjects/palettes) are
expected to be added under the same rules — see "Product lines" and "Adding
things" below.

All generated artifacts live under one `out/` root, named by what they are:

```
out/clay-png/   # line 1  — rendered clay: 1488 PNGs (93 × 8 palettes × 2 variants)
out/clay-svg/   # line 1b — the SAME PNGs byte-identical in .svg containers (derived, see below)
out/flat-svg/   # line 2  — true-vector flat geometry, 744 SVGs
```

`out/clay-png/` and `out/flat-svg/` are committed — they are the shipped
product. `out/clay-svg/` is a pure byte-identical derivation of the PNGs and
is generated on demand, not committed (see line 1b below).

## Product lines

### Line 1 — Clay renders (`out/clay-png/`, `out/clay-svg/`)

Soft 3D matte clay renders on a debossed grounded tray. The visual family is
locked (r8-2 recipe, see `docs/clay-recipe.md`): medium-rounded off-white
panel debossed like a shallow tray, subject standing on the recessed floor,
one pronounced elliptical contact shadow, light from upper left, pure seamless
white background.

Two shipped variants per subject per palette:

```
out/clay-png/{palette}/{group}-{state}.white.png        # original render, white bg
out/clay-png/{palette}/{group}-{state}.transparent.png  # rembg cutout of the SAME render
```

The transparent variant is derived from the white variant (single generation,
then cutout) — zero style divergence between the two by construction.

Because clay renders are lighting/shadow raster art they cannot be truly
vectorized without destroying the locked style. For consumers that require the
`.svg` file format, every PNG is wrapped byte-identical into a minimal SVG
container (`out/clay-svg/`):

```bash
python3 scripts/make_svg_wrappers.py            # wraps out/clay-png/ into out/clay-svg/
python3 scripts/make_svg_wrappers.py --check    # verify byte-identity, never writes
```

The wrappers are a pure derivation (deterministic script, `--check` gate), so
they are NOT committed — run the script after cloning or after regenerating
PNGs. The wrapper is visual-drift-free but still raster inside — no infinite
scaling, no CSS recolor. True flat-vector recoloring is line 2, not a
derivative of these renders.

### Line 2 — Flat vectors (`out/flat-svg/`)

The vector sibling: same 93 subjects, same eight palettes, same four palette
slots — drawn as flat SVG geometry instead of rendered clay. Infinite
scaling, ~0.5–2.3 KB per file, palette baked in at build time. Locked style
contract in `docs/flat-recipe.md` (viewBox 0 0 128 128, transparent bg,
subject band ~y=18..96, one contact-shadow ellipse at y=104).

```
out/flat-svg/{palette}/{group}-{state}.svg
```

No white/transparent variant split: flat SVGs are inherently transparent, so
the flat catalog is 93 × 8 = **744 SVGs**. Clay and flat are siblings, not
substitutes — clay carries warmth/texture, flat carries scale/flexibility.

## Cloning

The clay PNGs are stored with **git-lfs** (large binaries stay out of git
history). With git-lfs installed, a normal `git clone` pulls everything
automatically; if you cloned without LFS and see pointer files, run
`git lfs pull`.

## Usage

```bash
# Clay generation — needs DASHSCOPE_API_KEY (env or ~/.claude/.env fallback)
pip install -r requirements.txt                  # rembg / pillow / pymatting

python3 scripts/generate_clay_library.py --list                 # show all subjects
python3 scripts/generate_clay_library.py --dry-run --all        # print every prompt
python3 scripts/generate_clay_library.py --all                  # default palette: terracotta
python3 scripts/generate_clay_library.py --all --palette ocean
python3 scripts/generate_clay_library.py --subject error/not-found-404 --palette forest
python3 scripts/generate_clay_library.py --all --skip-existing  # resume-friendly

# Flat vectors — pure stdlib, no API key, deterministic
python3 scripts/build_flat_library.py --list
python3 scripts/build_flat_library.py --all
python3 scripts/build_flat_library.py --all --palette ocean
python3 scripts/build_flat_library.py --subject billing/upgrade
```

### Integrity gates (fail closed, never write)

```bash
python3 scripts/build_flat_library.py --verify   # rebuild-in-memory diff vs out/flat-svg
python3 scripts/make_svg_wrappers.py --check     # clay-svg wrappers embed PNGs byte-identical
```

Both gates fail on missing files, drift/hand-edits, and orphan files the
catalog cannot account for. Run them before shipping; they are the difference
between "generated" and "trusted".

## Adding things (the extension contract)

- **New subject**: one line in `SUBJECTS` (the clay script) + one clay
  template + one flat icon function. The parity check in
  `build_flat_library.py` fails closed until all three exist — drift between
  lines is impossible by construction.
- **New palette**: append to `PALETTES` in the clay script; every line that
  parses it picks it up automatically. Regenerate/build that palette folder.
- **New product line**: a new script + a new `out/<line>/` folder + a recipe
  doc in `docs/`. A line either shares the catalog (and gets the parity gate)
  or declares its own — but it must be script-generated and drift-checked.
  The wrappers (`clay-svg`) are the minimal example of a derived line.

## Constraints baked into the scripts

- Ship size **512×512**, per-PNG budget **≤300 KB** (downscale ladder
  512 → 448 → 384 with LANCZOS until the budget holds; hard failure otherwise).
- Clay model `wan2.7-image-pro` via the **async** DashScope route
  `image-generation/generation` with `X-DashScope-Async: enable`. The legacy
  `text2image/image-synthesis` endpoint returns `InvalidParameter url error`
  for this model — do not route through it.
- 3 retries per generation with backoff.

## Rules for consumers and agents

- **Do NOT recolor or hue-shift shipped PNGs.** The palette is measured and
  locked at generation time. Need a new color? Add a palette to the script
  and regenerate.
- **Do NOT hand-edit any shipped asset.** New subject = one line in
  `SUBJECTS` + one run. Hand edits fail the integrity gates.
- Dark themes: put the white variant on a dark card container (the
  `clay-card-icon` pattern). Never re-render the asset per theme — theme
  adaptation is the container's business, not the asset's.

## Known limits (honest remainder)

- Style adjudication is still human eyes; there is no automated similarity
  gate (a VL model can measure a palette but not "translucency").
- Clay family consistency across regenerations depends on DashScope model
  behavior staying stable for the same prompt.
- rembg keeps the near-white `#f9f9f9` tray (verified on pilot batch), but a
  future model/dependency change could shave it — spot-check cutouts when
  upgrading dependencies.
